## Architectural decision: routine architecture migration (2026-05-08)

**Trigger:** Project moved from Claude.ai chat-driven workflow (incognito-tab + paste-back manual operations) to GitHub-repo + Claude routines architecture with direct repo write access and Google Calendar MCP. Migration eliminates the prior protocol's "action 4 — persist Claude-produced files" by allowing Claude routines to write project files directly. Human role reduced from four actions to three: (1) execute trades from IBKR-paste output, (2) paste calendar prompts for one-off fresh-chat events (primarily screenshot capture), (3) paste IBKR screenshots.

**Inputs:** Prior `Claude_Task_Plan.md` (1053-line manual-operations version); `Strategy.md` revs through current; `Experiment_Parameters.md` rev 15+; the rev 3 single-session simplification accepted-risk note in `Experiment_Parameters.md`; the rev 4 four-session theater-auditor pattern in `Strategy.md` regime-router divergence-review section.

**Decision:** Three substantive changes to the experiment's operational architecture, plus terminology updates throughout `Strategy.md`, `Experiment_Parameters.md`, `Claude_Task_Plan.md`:

1. **M1 monthly fundamental sub-step A / sub-step B → M1a / M1b separate routines.** Sub-step A (strategy-blind regime scoring) becomes the M1a routine; sub-step B (strategy-mapping with reconciliation rules) becomes the M1b routine. Architectural blinding preserved by file handoff: M1a writes the regime scoring conclusion to `Monthly_Fundamental_RegimeScore.md`; M1a does NOT persist its underlying macro/policy/earnings inputs or its full reasoning chain. M1b is a separate routine with fresh context that reads only `Monthly_Fundamental_RegimeScore.md` for regime input. The earlier-rejected single-session two-step pattern (where both sub-steps shared one session's context window and Strategy.md prior revision documented "did not produce representational blinding because both sub-steps shared the same session context") is NOT what M1a/M1b implements — the routine boundary is a genuine context boundary, equivalent to the original incognito-session boundary for the architectural property being preserved. M1a routine prompt includes explicit blinding requirement (no strategy references in inputs or reasoning); M1b routine prompt includes explicit file-read scope limitation (read regime-scoring file only, NOT macro inputs).

2. **Adversarial reviews migrated from incognito-session + paste-back to queue-driven routine pipeline.** All structured adversarial reviews (pre-mortem reviews, regime-router divergence reviews, mark-to-market termination reviews, capital-redistribution reviews, scope-widening adjudication for Strategy C post-HYBRID gating) now use a queue file `Pending_Adversarial_Reviews.md` and three new routines: Adversarial Review Recommendation (capital-redistribution only), Adversarial Review Attacker, Adversarial Review Orchestrator. Triggering routines (M5 for divergence flags, kill-trigger detectors for M2M-termination, termination handlers for capital-redistribution) write entries to the queue with phase due dates; the AR routines fire daily and process queue items at their phase. File handoff replaces paste-back: each routine writes its output to a designated file path; downstream routine reads only the upstream-output file plus the artifact under review. No human action required for any structured adversarial review under this architecture.

3. **`Strategy.md` regime-router divergence review four-session pattern → two-routine pattern, aligning with `Experiment_Parameters.md` rev 3 simplification.** `Strategy.md` previously specified four sessions (Fundamental author / Attacker / Judge / Theater Auditor) with the theater-audit step architecturally separated to eliminate judge self-certification. `Experiment_Parameters.md` rev 3 had simplified to single-session-attacker + in-conversation orchestrator review, but this simplification had not been propagated to `Strategy.md`'s divergence-review section — pre-existing inconsistency between the two documents. The migration resolves the inconsistency by aligning `Strategy.md` to the two-routine pattern (Attacker routine + Orchestrator routine, orchestrator self-certifies theater-check). The standalone Theater Auditor stage from `Strategy.md` rev 4 is NOT preserved in migration scope; the `Strategy.md` rev 4 architectural addition (Session 4 specifically added to address judge self-certification per rev 2 defect) is therefore reduced to orchestrator self-certification. This is an explicit reduction in rigor, accepted per the migration's scope-bounding choice. Substantive policy preserved: theater-check tiebreaker (CONVERGENT → default DO-NOT-ACTIVATE), ambiguity defaults (non-committal verdict / conditional-on-future-evidence verdict → DO-NOT-ACTIVATE), logging requirements.

**Reasoning:**

- *Why route M1 sub-steps to separate routines instead of a single-routine two-phase pattern.* User initially proposed a single-prompt-two-phase pattern (Phase 1 regime scoring under one set of constraints, Phase 2 strategy mapping under another, both within the same prompt). Discussion surfaced that single-routine-two-phase preserves prior-phase reasoning and inputs in the model's context window when the second phase generates, which is exactly the "single-session two-step blinding does not blind" defect that `Strategy.md`'s prior revision had rejected. Two-routine file handoff was strictly better than single-routine-two-phase on the blinding axis at comparable operational cost — both are auto-running with no human paste-back, but the two-routine version genuinely strips the reasoning chain from the second phase's context. User accepted Option 2 (two routines) on this basis.

- *Why three-routine pipeline for capital redistribution but two-routine for other adversarial review types.* `Experiment_Parameters.md` rev 3 simplified all adversarial reviews from three-session to single-session on operational-cost grounds (manual incognito-tab + paste-back unsustainable across many reviews). Under routine architecture, that operational-cost rationale is gone — routines fire automatically. Capital redistribution specifically benefits from preserving the original three-routine pipeline (Recommendation + Attacker + Orchestrator) because the recommendation step is genuinely independent from the attacker step (not a self-certifying integration). For pre-mortem / divergence / M2M-termination, the original three-session design's value was in having a separate session-isolated judge after the attacker — that's a different architectural property than the recommendation-attacker separation. Restoring the separate-judge step for those would constitute a substantive enhancement beyond migration scope; deferred to a possible future revision (a fourth routine: Theater Auditor) if accumulated theater-check flags suggest self-certification is producing under-detection of CONVERGENT framing.

- *Why prompt-discipline blinding for the Attacker routine instead of structural blinding.* Under Claude.ai routines as currently available, a routine has full repo read access by default. There is no per-routine read-scope restriction enforceable structurally. The original incognito-Claude.ai-conversation pattern provided structural blinding because incognito sessions had no project access at all. Under the routine architecture, the Attacker routine's prompt is the enforcement mechanism: explicit instructions forbidding reads of `Decision_Log.md`, prior adversarial review files, `Strategy.md` sections beyond the artifact under review, and any other repo file not explicitly authorized. Auditable via the routine's tool-call log — if the attacker reads Decision_Log.md the trace is visible. Accepted-risk note recorded in `Experiment_Parameters.md` operational requirements section.

- *Why preserve historical pre-mortem text rather than rewriting it for new terminology.* Pre-mortems in `Strategy.md` are historical artifacts from the pre-launch review cycles. Their internal references to "sub-step A," "Session 1 / 2 / 3 / 4," and "incognito session" describe the architecture as it was at the time of writing. A terminology bridge note added at the top of the Pre-mortems section maps historical terminology to current routine architecture. The pre-mortem text below the bridge is preserved verbatim. Operational behavior follows current routine architecture per `Claude_Task_Plan.md` and the operationally-binding sections of `Strategy.md` (regime router section), not the historical pre-mortem text.

**Pre-existing inconsistency resolved during migration:** `Strategy.md` divergence-review section specified a four-session pattern (rev 4) while `Experiment_Parameters.md` specified single-session-attacker + orchestrator (rev 3). The migration aligns `Strategy.md` to the two-routine pattern matching `Experiment_Parameters.md`'s simplification. Future readers should be aware that `Strategy.md` rev 4's standalone Theater Auditor stage was a deliberate architectural addition to address judge self-certification (per rev 2 defect from the regime-router pre-mortem cycle). Reducing to orchestrator self-certification is therefore an explicit acceptance of self-certification risk for divergence reviews. If empirical theater-check rates over multiple divergence reviews suggest self-certification is producing under-detection of CONVERGENT framing, restoring a separate Theater Auditor routine (fourth routine in the pipeline) is the path back to rev 4 rigor — that is a known adjustable parameter, not a defect.

**Accepted-risk summary (consolidated):**

- *Prompt-discipline blinding under routine architecture.* The Attacker routine's restriction to reading only authorized files is enforced by prompt instruction, not by structural sandboxing. Auditable via tool-call log. Mitigation if violations observed: tighten prompt language, monitor in monthly theater-check survey.
- *Orchestrator self-certification on theater-check.* Pre-mortem / divergence / M2M-termination reviews use orchestrator self-certification of CONVERGENT/DIVERGENT/MIXED framing instead of a separate Theater Auditor stage. Mitigation if accumulated theater-check rates suggest under-detection: add fourth routine (Theater Auditor) in future revision.
- *Single model weights across all routines.* Hard-wired biases cut across routine boundaries regardless of context isolation. Same residual limitation that existed under incognito-session pattern; not introduced by migration.
